# HypothesiAI Database Architecture (Stage 2)

This directory contains the PostgreSQL & Supabase-compatible relational database foundation for HypothesiAI.

---

## The 15 Core Relational Entities

1. **`users`**: Identity, authentication records, and user roles (compatible with Supabase `auth.users`).
2. **`papers`**: Ingested scientific literature metadata, publication details, status tracking (`uploaded`, `processing`, `parsed`, `indexed`, `failed`), and object storage keys.
3. **`paper_sections`**: Fine-grained structural segmentation (Abstract, Introduction, Methods, Results, Limitations, Future Work, etc.) with page boundaries and bounding box coordinates from PyMuPDF.
4. **`extracted_entities`**: Extracted domain concepts (problems, methods, datasets, metrics, limitations, future work, claims) with confidence scores, page numbers, and vector embedding IDs.
5. **`entity_aliases`**: Deduplication and canonical mapping (via RapidFuzz token matching and cosine vector similarity).
6. **`paper_relationships`**: Cross-paper citation, methodology extension, evaluation, and conflict links.
7. **`topics`**: Topic clusters generated by BERTopic, including c-TF-IDF keyword representations and coherence scores.
8. **`limitation_clusters`**: HDBSCAN clusters of limitation statements extracted from papers.
9. **`future_work_clusters`**: HDBSCAN clusters of future work statements.
10. **`research_patterns`**: Frequent research-pattern and rare combination mining outputs (FP-Growth / Apriori) capturing support, confidence, lift, and rarity scores.
11. **`contradictions`**: Cross-Encoder NLI detected contradictions between premise papers and hypothesis papers.
12. **`research_gaps`**: Multi-signal synthesized research gap candidates with composite confidence scores and individual signal weights.
13. **`gap_evidence`**: Fine-grained provenance linking research gaps directly to papers, sections, text snippets, and signal metrics.
14. **`hypotheses`**: Synthesized research hypotheses with rationales, methodologies, evaluation metrics, and verified paper citations.
15. **`analysis_runs`**: Audit logging and telemetry for analytical pipeline execution runs.

## Migration System

Migrations are located in `database/migrations/`:
- `001_core_schema.sql`: Table definitions, primary keys, foreign keys, cascades, and constraints.
- `002_indexes_and_triggers.sql`: Performance B-Tree indexes, GIN JSONB indexes, and automatic timestamp update triggers.

### Running Migrations

Using the Backend TypeScript migration CLI:
```bash
# Apply pending migrations
npm --prefix backend run db:migrate

# Verify all 15 tables, foreign keys, and indexes
npm --prefix backend run db:verify
```

When using `docker-compose up -d postgres`, `schema.sql` is automatically mounted into `/docker-entrypoint-initdb.d/01_schema.sql` to initialize the database immediately.
